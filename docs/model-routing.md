# Подбор моделей под среду

Агент рекомендует исполнителя по явному списку доступных моделей. Наличие установленного Cursor или Codex не означает, что доступны все модели провайдера. Команда не входит в аккаунт и не переключает модель скрытно.

```powershell
python tools/strateg.py capabilities inspect
python tools/strateg.py capabilities template --output inventory.local.json
python tools/strateg.py route --inventory inventory.local.json --role critic
```

`inspect` проверяет Python и наличие ffmpeg, whisper, cursor, claude, codex в PATH. Проверка не запускает найденные программы, не читает `.env` и не проверяет API-ключи. Локальные пути в выводе могут содержать имя пользователя: не включайте такой вывод в публичный отчёт без очистки.

## Заполнение списка

Шаблон создаётся с пустым `models`; существующий файл не перезаписывается. Добавьте точные ID моделей, которые видны в вашей среде. DeepSeek, Gemini, Grok, Claude и GPT — семейства для матрицы испытаний, а не исполняемые ID.

Пример элемента (это вымышленные значения, не каталог моделей):

```json
{
  "id": "exact-id-from-your-environment",
  "provider": "provider-name",
  "roles": ["extractor", "analyst"],
  "available": true,
  "evidence": "Выбрана в интерфейсе среды; дата проверки и ссылка на результат",
  "price": null
}
```

Роли: `extractor`, `analyst`, `researcher`, `critic`, `strategist`. Назначение роли означает, что пользователь или среда считают модель пригодной для неё; программа не оценивает интеллект модели. Для `available: true` обязательно основание `evidence`. Это заявление в inventory, а не независимо подтверждённый доступ: при отказе провайдера установите `available: false` и повторите подбор.

Поле `price` — сумма стоимости 1 млн входных и 1 млн выходных токенов в USD, без кэша; `price_basis` из шаблона фиксирует эту общую расчётную нагрузку. Это условный ориентир для выбора, не прогноз стоимости конкретной задачи. Не смешивайте с месячной подпиской; неизвестная цена — `null`, не ноль.

Из доступных моделей с нужной ролью выбирается минимальная известная цена. Если есть модели без цены, результат прямо говорит, что полного сравнения нет. Если все цены неизвестны, используется первая подходящая запись и экономичность не утверждается. Единственная подходящая модель помечается как запасной режим. Нет подходящей модели — отказ с кодом 1; ошибочный inventory — код 2. Роль критика не заменяется исполнителем без явно назначенной роли.

## Cursor, Claude Code, Codex и веб-чаты

Для каждой среды ведите свой inventory с версией приложения и датой проверки. Файлы и терминал, веб-поиск, изображения, субагенты и выбор модели — разные возможности. В обычном веб-чате исполнение CLI может быть недоступно даже при доступной модели. Там нужен ручной перенос материалов и результатов, отражённый в отчёте. Нельзя считать такой проход равным автономному проходу в Cursor.

Первый этап — подтверждённый список и объяснимый выбор. Автоматическое получение каталога конкретного провайдера и реальное переключение требуют адаптера этой среды; в этой версии их нет. Результаты испытаний каждой точной модели записываются отдельно, включая ошибки инструментов и помощь человека.

## Оценка перед запуском

После понимания задачи модель текущего чата составляет короткий список операций и предлагает режим с объяснением. Пользователь выбирает режим и лимит до выполнения основных операций. Команда `python tools/strateg.py route-preview --inventory inventory.local.json --request request.json --budget-usd 1.00` строит три плана. Запуск исполнителей остаётся за средой.

Для оценки дополни каждую модель полями `level` (`economy`, `balanced`, `maximum`), `context_tokens` и `rates_usd_per_million`, например `{"input":"0.50","output":"2.00"}`. Уровень назначается по пригодности, независимо от цены. Старое поле `price` служит только прежней команде `route`. При неизвестном тарифе или размере контекста модель не включается в оценённый маршрут. Нулевые ставки указываются только для подтверждённого бесплатного доступа.

Пример `request.json`:

```json
{
  "suggested_mode": "balanced",
  "reason": "Решение перераспределяет бюджет. Нужна независимая проверка экономики.",
  "operations": [
    {"id": "numbers", "role": "code"},
    {"id": "draft", "role": "strategist", "input_tokens": 4000, "max_output_tokens": 1500},
    {"id": "economics-review", "role": "critic", "from_mode": "balanced", "input_tokens": 2500, "max_output_tokens": 600},
    {"id": "promises-review", "role": "critic", "from_mode": "maximum", "input_tokens": 2000, "max_output_tokens": 500}
  ]
}
```

В `input_tokens` учитывай инструкции, материалы и контекст, переданные конкретному исполнителю. При дорогом режиме добавляй разные вопросы критики только там, где они могут повлиять на решение. Независимые вопросы можно выполнять параллельно, итоговую сверку — после ответов. Оценивай и её отдельной операцией, если требуется модель. Предварительная сумма не включает повторные вызовы и текущий чат. Принудительное соблюдение лимита и итоговый расход задачи требуют исполнительного адаптера и показаний среды.
