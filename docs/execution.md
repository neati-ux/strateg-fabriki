# Исполнение маршрута и расходы

`route-preview` показывает рекомендацию и три базовых режима. Чтобы добавить кастомный маршрут, передайте в `request.json` поле `custom`, например `{"draft":["anthropic","exact-model-id"]}`. Карта назначает модель каждой модельной операции. При выборе модели учитываются роль, контекст и тариф. Для специальных возможностей задайте `requires` у операции и `features` у модели.

После согласия пользователя:

```powershell
python tools/strateg.py -p demo execution approve --task task-1 --request request.json --inventory inventory.local.json --mode recommended --billing api --budget-usd 1 --scope task
python tools/strateg.py -p demo execution status --task task-1
python tools/strateg.py -p demo execution run --task task-1 --session session-1 --action draft
python tools/strateg.py -p demo execution report --task task-1 --details
```

Режим можно выбрать явно: `economy`, `balanced`, `maximum`, `custom`. `--scope task|session|action` задаёт масштаб отчёта и может быть переопределён при просмотре. У сессии нужен `--session`, у действия `--action`. Одно действие включает вход и ответ, а время отчёта — сумма длительностей действий. Токены и подписочный лимит доступны в `--details`.

Для прямого запуска Anthropic используются утверждённый `prompt` и `ANTHROPIC_API_KEY` из окружения. Сумма рассчитывается по токенам ответа API и тарифам утверждённого каталога. Это не счёт провайдера. Для роли `code` операция может содержать `calculation` с полями `kind` и `inputs`. `depends_on` перечисляет предшествующие операции. Независимые операции можно запустить `execution run-group --task task-1 --session session-1 --actions review-a review-b --workers 2`. Общий лимит проверяется по группе и повторно перед каждым вызовом.

Для среды, которая исполняет работу сама, используй `execution reserve` перед запуском и `execution record --receipt receipt.json` после. Квитанция содержит `seconds`, опциональные `cost_usd`, `input_tokens`, `output_tokens`. Для подписки можно указать `limit_percent` как расход именно этого действия, `limit_window` и `limit_evidence`. При неполном покрытии или разных окнах общего процента нет. Подписочный процент не вычисляется из токенов. Если ответ потерян, резерв остаётся до получения данных. Не повторяй вызов, пока не разрешена неопределённость.

`execution status` показывает сохранённый результат и доступные шаги. Завершённый вызов не запускается повторно под тем же ID. SQLite хранит утверждённый план, результаты и резервы локально, вне выпуска. Проверку качества содержания и принятие результата пока ведёт агент по процедурам проекта. Бюджет ограничивает оценку перед вызовом, расхождение цены каталога и биллинга возможно.

`strateg collect` принимает путь, URL или запись. Документы идут через `ingest`, веб-страницы сохраняются со снимком, записи — с исходником и расшифровкой или кадрами. `verify` по умолчанию читает сохранённые источники. Для доверенных расчётов в `analysis/` есть отдельный `--run-calculations`.

Профиль (`--profile preferences.local.json`) задаёт свои значения по умолчанию: `mode`, `billing`, `scope`, `budget_usd`, `workers` и, при необходимости, `custom`. Например `{"mode":"balanced","billing":"api","scope":"session","budget_usd":"1.00","workers":2}`. Явные параметры команды имеют приоритет. Для `custom` карта из запроса имеет приоритет над картой из профиля. При отсутствии профиля используются рекомендованный режим, отчёт по задаче и один исполнитель.

`execution advance --task task-1 --session session-1` выполняет доступные операции утверждённого плана. Опциональные `required_json_keys` проверяют форму ответа, `after_gate` связывает запуск с существующей развилкой, `project_inputs` фиксирует версии входных файлов проекта. После изменения входа нужен новый план. Опциональный `retries` (0–2) разрешает повтор известного отклонённого результата при остатке бюджета. Неопределённый расход остаётся в резерве. `advance` не повторяет неудачные вызовы автоматически. Смысл стратегии оценивается отдельно.

Операция может иметь явный `fallback: [provider, model_id]`. Оценка показывает стоимость первой попытки и сумму с одним запасным вызовом. После известного отклонения доступный исполнитель меняется на согласованного запасного, если бюджет позволяет. `advance` может взять его при следующем запуске. Потерянный ответ оставляет резерв и останавливает автоматический повтор. Режим не переносит задачу к неутверждённому провайдеру.

## Связь с семью шагами

1. `workflow next` определяет стадию по сохранённым документам, отметкам и решениям человека. В Claude Code этот статус виден при старте сессии, в Cursor доступен через правило проекта или MCP `workflow_next`.
2. `workflow offer --brief "Сформулируй стратегию удержания" --inventory inventory.local.json --output step.local.json` готовит план текущего шага и показывает режимы со сметой. Запрос можно взять из карточки, опустив `--brief`. `workflow prepare` сохраняет план отдельно от оценки. Для кастомной карты есть `--custom assignments.local.json`.
3. Покажи пользователю меню. После явного выбора утверди план через `execution approve`. Для единого лимита нескольких стадий укажи `--work-id strategy-1 --work-budget-usd 3` при первом утверждении и тот же `--work-id` в следующих стадиях. Лимит каждой операции проверяется и по её стадии, и по общей задаче. Итог по стадиям: `execution report --task ИД_СТАДИИ --whole-work --scope task --details`.
4. Выполни `execution advance` либо работай в выбранной среде и передай её результат в `workflow review --file result.local.json`. Для результата из журнала есть `workflow review --task ИД_СТАДИИ`. Команда проверяет формат, ссылки на активные основания, обязательные варианты, возражения, обещания и поля замера. Если фактов нет, создай их через существующие команды реестра. Пересчитай маршрут, если обновились зафиксированные входы.
5. Прочитай результат и проверь связь выводов с источниками. После этого `workflow apply --task ИД_СТАДИИ --review "что именно сверено"` записывает согласованные документы и точку продолжения. Для другого лаунчера можно указать `--file`. Ссылки на факты с числовыми расхождениями останавливают запись. Развилки 1, 4 и 7 остаются в `gate confirm`. При перерыве повтори `workflow next`.

Артефакты `*.local.json` и журнал исполнения хранятся локально. Маршрут шага опирается на зарегистрированные локальные материалы. Если часть источника отсечена лимитом контекста, она помечается как непрочитанная. Исследовательский поиск и внесение новых фактов выполняют имеющиеся навыки и команды.

### Учёт OpenCode

После `execution reserve` можно передать JSONL одного запуска (`opencode run --format json`) команде `execution record-opencode --task ИД --action ИД --events run.local.jsonl`. Она извлекает ответ, время между событиями, токены и оценку стоимости, которую сообщил OpenCode. Повторный импорт того же набора завершённых шагов отклоняется. Для подписки импортируются токены, а процент лимита по этим событиям не вычисляется. При неполном журнале сверяй расход отдельно. Формат: https://opencode.ai/docs/cli/commands/.

Автоматический запуск OpenCode сюда пока не входит: CLI должен сначала дать способ заранее ограничить стоимость и доступные инструменты для конкретного вызова. Логи могут содержать ответы и данные проекта. Храни их под локальными именами и не включай в пакет.

## Дополнительные функции ядра

Для непосредственного применения назначений используй `capabilities claude-sync --assignments roles.local.json`. Для автоматического прохождения динамического сайта — `ux-capture --scenario scenario.json`. Оба маршрута описаны в [инструкции](browser-and-model-sync.md).

- `capabilities mcp-config --host cursor|claude|opencode|opencode-v1` выводит конфигурацию под текущую папку и Python. Для Cursor её можно сохранить как `.cursor/mcp.json`, для OpenCode объединить с `opencode.json`. Существующий файл команда не перезаписывает. `strateg.cmd` пробует реально запустить Python, а при необходимости использует `STRATEG_PYTHON`.
- `execution handoff --task T --action A --output action.local.json` сохраняет утверждённую модель, задание и ограничения для внешней среды. Резерв и импорт её квитанции выполняются отдельно. Не публикуйте файл, в нём может быть содержимое проекта.
- `gemini` и `deepseek` поддерживаются как прямые текстовые API. Gemini использует `GEMINI_API_KEY` или `GOOGLE_API_KEY`. DeepSeek — `DEEPSEEK_API_KEY`. Для DeepSeek при отсутствии отдельного счётчика входа резерв консервативно исходит из полного заявленного контекста модели. Цена результата считается по учёту токенов и каталогу. Мультимодальные вызовы и инструменты в прямом адаптере не включены.
- `research knowledge churn`, `research add`, `research close`, `research list` ведут исследование и проверяют актуальность оснований. `research discover` использует внешний Brave API и посылает туда явный запрос. По умолчанию пользуйтесь веб-поиском среды. Для `discover` нужен `BRAVE_SEARCH_API_KEY`, этот вызов не относится к модельному бюджету `execution`.
- `locate S-001 "цитата"` печатает строки сохранённого источника. `revise S-001 --superseded-by S-002 --reason "новая выгрузка"` связывает версии и ставит зависимые тезисы на пересмотр. Прошлые решения сохраняются.

`capabilities claude-profile --assignments roles.local.json --output-dir NEW_DIRECTORY` собирает отдельные Markdown-профили Claude Code. В `roles.local.json` указываются роли и ID, например `{"extractor":"haiku","critic":"sonnet"}`. Существующие профили проекта сохраняются. `mcp-config --playwright-executable PATH` добавляет уже установленный Playwright MCP с отдельным контекстом браузера. Веб-страницы остаются данными. Сохраняйте исходный скриншот и наблюдения через `collect PATH --observation NOTES`.
