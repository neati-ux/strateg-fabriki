# Протокол до запуска

Один новый учебный кейс о выдаче заказов в музее. Источники и реплики руководителя одинаковы для трёх вариантов. Обычный чат отвечает напрямую. Два других варианта получают один и тот же результат табличного расчёта и используют инструкции аналитика и критика из репозитория. В одном все роли исполняет модель 1.5B, в другом только анализ передан модели 0.5B. Критик и автор ответа в обоих вариантах — 1.5B. Это изолированная проверка ролей при фиксированном сценарии с выдачей и пересмотром записки. Сквозной интерактивный путь в Cursor и Claude здесь не воспроизводится.

Оценка по пяти признакам, каждый даёт 0 или 1 балл:
1. Верный числитель, знаменатель и окно основной метрики.
2. Из четырёх строк получены три уникальных обращения, из них два про код.
3. В ответе явно указано, что по тематической подборке нельзя установить главную причину среди всех посетителей.
4. В бюджете выбран реализуемый пакет и предложен тест внутри площадок.
5. После запрета случайного распределения запуск приостановлен, эффект не объявлен; в пределах 14 дней есть конкретный результат для директора.

Первые четыре признака оцениваются по первой записке, пятый по ответу на новое условие. Публикуются обе записки, промежуточные ответы, число вызовов, токены, время загрузки и генерации. Тест запускается без ключа коммерческого провайдера. Время тарификации VM и стоимость труда человека в токенах не выражаются. Порядок фиксирован, варианты запускаются в отдельных процессах на одном раннере; один прогон даёт наблюдение, а не оценку повторяемости.
